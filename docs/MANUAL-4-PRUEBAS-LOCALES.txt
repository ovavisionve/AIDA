2. LEVANTAR LA BASE DE DATOS Y REDIS (Docker)
================================================================================

Docker se encarga de PostgreSQL 16 y Redis 7. No necesitas instalarlos
manualmente.

PASO 2.1: Abrir Docker Desktop
  - Asegurate de que Docker Desktop esta corriendo
  - En Windows: busca "Docker Desktop" en el menu de inicio y abrelo
  - En Mac: busca Docker en Spotlight
  - Espera hasta que diga "Docker Desktop is running"

PASO 2.2: Levantar los servicios
  1. Abre una terminal/cmd
  2. Navega a la carpeta del proyecto:
     cd /ruta/a/AIDA
  3. Ejecuta:
     docker compose up -d db redis
  4. Espera 10-20 segundos
  5. Verifica que estan corriendo:
     docker compose ps

  Debes ver algo como:
    NAME            STATUS
    aida_postgres   Up (healthy)
    aida_redis      Up (healthy)

  Si ambos dicen "Up" y "(healthy)": PERFECTO, sigue al paso 3.

  Si alguno dice "Exit" o no aparece:
    → Ejecuta: docker compose logs db redis
    → Lee el error. Lo mas comun:
      - "port already in use": Ya hay un PostgreSQL o Redis corriendo
        Solucion: Para el servicio que ocupa el puerto, o cambia el puerto
        en docker-compose.yml (ej: "5433:5432" en vez de "5432:5432")

NOTA: Los datos se guardan en volumenes Docker. Si paras y vuelves a
  levantar, tus datos seguiran ahi. Para BORRAR todo y empezar de cero:
  docker compose down -v   (la -v borra los volumenes)

3. LEVANTAR EL BACKEND (FastAPI)
================================================================================

PASO 3.1: Crear el archivo .env
  1. Ve a la carpeta backend:
     cd /ruta/a/AIDA/backend
  2. Copia el archivo de ejemplo:
     - En Linux/Mac: cp .env.example .env
     - En Windows:   copy .env.example .env
  3. El archivo .env ya viene con valores por defecto que funcionan
     con Docker local. NO necesitas cambiar nada para pruebas locales.

  Los valores por defecto son:
    DATABASE_URL=postgresql+asyncpg://aida:aida_secret_2024@localhost:5432/aida_db
    REDIS_URL=redis://localhost:6379/0
    ENVIRONMENT=development
    DEBUG=true
    SECRET_KEY=CAMBIAR-EN-PRODUCCION-usar-openssl-rand-hex-64
    ALLOWED_ORIGINS=["http://localhost:3000","http://localhost:3001","http://localhost:3002","http://localhost:3003","http://localhost:3004","http://localhost:3005","http://localhost:3100"]

PASO 3.2: Crear entorno virtual de Python
  1. Estando en /ruta/a/AIDA/backend:
  2. Crear el entorno virtual:
     python -m venv venv
  3. Activar el entorno virtual:
     - Linux/Mac:  source venv/bin/activate
     - Windows:    venv\Scripts\activate
     Cuando se active, veras (venv) al inicio de la linea de la terminal.

PASO 3.3: Instalar dependencias
  1. Con el entorno virtual activado, ejecuta:
     pip install -r requirements.txt
  2. Esto toma 2-5 minutos la primera vez
  3. Debes ver al final: "Successfully installed ..." con muchos paquetes

PASO 3.4: Arrancar el backend
  1. Con el entorno virtual activado, ejecuta:
     uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
  2. La primera vez que arranca, el backend:
     a) Crea todas las tablas en PostgreSQL (40 tablas)
     b) Detecta que no hay usuarios → ejecuta el SEED automaticamente
     c) Crea: admin, roles, permisos, clientes Santoni y Electro Caribe
  3. Debes ver en la terminal mensajes como:
     - "creating_tables"
     - "database_tables_ready"
     - "no_users_found_running_seed"
     - "Creando permisos... 60+ permisos configurados"
     - "Creando roles..."
     - "Super admin creado: admin@aida.com.ve / Admin2024!"
     - "Cliente 1: Alimentos Santoni C.A. (SAP B1)"
     - "  Admin: carlos.santoni@arrozsantoni.com.ve / Santoni2025!"
     - "Cliente 2: Distribuidora Electro Caribe C.A."
     - "  Admin: luis.perez@electrocaribe.com.ve / Electro2025!"
     - "seed_completed_admin_created"
     - "Uvicorn running on http://0.0.0.0:8000"

  4. IMPORTANTE: Copia y guarda las API Keys que aparecen en los logs.
     Solo se muestran UNA VEZ durante el seed.
     Ejemplo: "API Key: aida_J312456783_a1b2c3d4e5f6..."

PASO 3.5: Verificar que el backend esta vivo
  1. Abre tu navegador
  2. Ve a: http://localhost:8000/health
  3. Debes ver:
     {"status":"ok","version":"1.0.0","database":"connected"}
  4. Ve a: http://localhost:8000/api/docs
  5. Debes ver la interfaz Swagger con todos los endpoints

DEJA ESTA TERMINAL ABIERTA. El backend debe seguir corriendo.

4. LEVANTAR LOS PORTALES FRONTEND
================================================================================

Necesitas OTRA terminal (no cierres la del backend).

PASO 4.1: Instalar dependencias del frontend
  1. Abre una nueva terminal
  2. Ve a la carpeta frontend:
     cd /ruta/a/AIDA/frontend
  3. Instala todo:
     npm install
  4. Esto toma 1-3 minutos. Instala dependencias de TODOS los portales.

PASO 4.2: Levantar todos los portales a la vez
  OPCION A — Todos juntos (mas facil):
    npm run dev
    Esto arranca los 7 portales al mismo tiempo con Turbo.
    Veras logs intercalados de todas las apps.

  OPCION B — Uno por uno (mas control):
    Abrir terminales separadas para cada portal:

    Terminal 1: cd /ruta/a/AIDA/frontend && npm run dev:admin
    Terminal 2: cd /ruta/a/AIDA/frontend && npm run dev:client
    Terminal 3: cd /ruta/a/AIDA/frontend && npm run dev:facturador
    Y asi para cada uno...

  OPCION C — Solo los que necesites:
    Si solo quieres probar la landing:
      cd /ruta/a/AIDA/frontend/apps/landing && npm run dev

    Si quieres probar el admin:
      npm run dev:admin

PASO 4.3: URLs de cada portal

  Una vez arrancados, los portales estan en estas URLs:

8. TROUBLESHOOTING LOCAL
================================================================================

PROBLEMA: "docker compose up" falla
  → Verifica que Docker Desktop esta abierto y corriendo
  → En Windows: el icono de la ballena en la bandeja debe estar verde

PROBLEMA: "pip install" falla con "error: Microsoft Visual C++ required"
  → Solo en Windows: necesitas instalar Build Tools para C++
  → Descarga: https://visualstudio.microsoft.com/visual-cpp-build-tools/
  → Instala seleccionando "Desktop development with C++"

PROBLEMA: El backend no arranca, dice "Connection refused" a PostgreSQL
  → Verifica: docker compose ps → aida_postgres debe estar "Up"
  → Si no esta: docker compose up -d db
  → Si ya esta pero no conecta: verifica que el .env tiene
    DATABASE_URL=postgresql+asyncpg://aida:aida_secret_2024@localhost:5432/aida_db

PROBLEMA: El backend arranca pero el seed no corre
  → El seed solo corre si NO hay usuarios en la BD
  → Si ya corrio antes, los datos ya estan
  → Para forzar re-seed: para todo, borra la BD y vuelve a empezar:
    docker compose down -v
    docker compose up -d db redis
    (espera 10s)
    uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload

PROBLEMA: "npm run dev" falla en el frontend
  → Verifica que hiciste "npm install" en la carpeta /frontend
  → Si da error de turbo: npm install turbo --save-dev
  → Si da error de dependencias: rm -rf node_modules && npm install

PROBLEMA: Puerto ocupado (ej: "EADDRINUSE ::: 3000")
  → Otro proceso usa ese puerto
  → En Linux/Mac: lsof -i :3000 → ver que proceso es → kill -9 [PID]
  → En Windows: netstat -ano | findstr :3000 → taskkill /PID [PID] /F
  → O simplemente cierra la otra terminal que este corriendo algo

PROBLEMA: Login dice "Error de conexion" o "Network Error"
  → Verifica que el backend esta corriendo en otra terminal
  → Verifica: http://localhost:8000/health
  → Si funciona el health pero no el login: abre DevTools (F12) →
    Console → busca el error exacto

PROBLEMA: Login funciona pero dice "403 Forbidden"
  → El usuario no tiene el rol correcto
  → Verifica que el seed corrio correctamente
  → Revisa los logs del backend (la terminal donde corre uvicorn)

PROBLEMA: Los portales cargan pero todo esta en blanco
  → Puede faltar la variable NEXT_PUBLIC_API_URL en el entorno
  → Para local, los portales estan configurados para usar
    http://localhost:8000/api/v1 por defecto
  → Si no funciona, crea un archivo .env.local en la carpeta del portal:
    echo "NEXT_PUBLIC_API_URL=http://localhost:8000/api/v1" > .env.local
