1. RESUMEN: COMO FUNCIONA ESTE MANUAL
================================================================================

Este manual te permite probar TODA la plataforma AIDA usando los portales
ya desplegados en Vercel. No necesitas levantar ningun frontend localmente.

El unico paso local es ejecutar el seed del backend para crear los 2 clientes
de prueba (Alimentos Santoni y Electro Caribe) en la base de datos en la nube.
Esto simula el onboarding de 2 empresas reales con perfiles distintos.

  FLUJO:
    1. [LOCAL - una sola vez] Ejecutar seed para crear datos de prueba
    2. [NAVEGADOR] Probar cada portal en las URLs de Vercel
    3. [NAVEGADOR] Verificar funcionalidad completa (30+ pruebas)

  QUE NECESITAS:
    - Navegador web (Chrome, Firefox, Edge)
    - Acceso a internet
    - Python 3.11+ (solo para ejecutar el seed una vez)
    - Las URLs de tus servicios desplegados (paso 3)


================================================================================
2. PREREQUISITO: CREAR LOS 2 CLIENTES DE PRUEBA (LOCAL)
================================================================================

Este paso solo se ejecuta UNA VEZ. Crea los datos iniciales en la base
de datos en la nube (Neon) para que los portales tengan con que trabajar.

PASO 2.1: Clonar el repo (si no lo tienes)
  git clone https://github.com/TU_USUARIO/AIDA.git
  cd AIDA/backend

PASO 2.2: Crear entorno virtual e instalar dependencias
  python -m venv venv
  - Linux/Mac:  source venv/bin/activate
  - Windows:    venv\Scripts\activate
  pip install -r requirements.txt

PASO 2.3: Configurar las variables de entorno para conectar a la nube
  Crea un archivo .env en la carpeta backend con estos valores:

  DATABASE_URL=TU_DATABASE_URL_DE_NEON
  REDIS_URL=TU_REDIS_URL_DE_UPSTASH
  ENVIRONMENT=qa
  DEBUG=true
  SECRET_KEY=TU_SECRET_KEY
  ALLOWED_ORIGINS=["*"]

  IMPORTANTE: Usa las MISMAS URLs de Neon y Upstash que configuraste en
  Railway (ver Manual 1). Asi el seed escribe en la misma base de datos
  que usa el backend desplegado.

  Ejemplo real:
    DATABASE_URL=postgresql+asyncpg://neondb_owner:abc123@ep-cool-rain-456.us-east-2.aws.neon.tech/neondb?ssl=require
    REDIS_URL=rediss://default:xyz789@us1-shiny-fish-12345.upstash.io:6379

PASO 2.4: Ejecutar el backend una vez para que corra el seed
  uvicorn app.main:app --host 0.0.0.0 --port 8000

  La primera vez que arranca, el backend detecta que no hay usuarios y
  ejecuta el SEED automaticamente. Veras en la terminal:

    - "no_users_found_running_seed"
    - "Creando permisos... 60+ permisos configurados"
    - "Creando roles..."
    - "Super admin creado: admin@aida.com.ve / Admin2024!"
    - "Cliente 1: Alimentos Santoni C.A. (SAP B1)"
    - "  Admin: carlos.santoni@arrozsantoni.com.ve / Santoni2025!"
    - "Cliente 2: Distribuidora Electro Caribe C.A."
    - "  Admin: luis.perez@electrocaribe.com.ve / Electro2025!"
    - "seed_completed_admin_created"

  IMPORTANTE: Copia y guarda las API Keys que aparecen en los logs.
  Solo se muestran UNA VEZ durante el seed.
  Ejemplo: "API Key: aida_J312456783_a1b2c3d4e5f6..."

PASO 2.5: Verificar que los datos se crearon
  Abre tu navegador y ve a:
    https://TU_URL_BACKEND/health
  (ejemplo: https://aida-production-a1b2.up.railway.app/health)

  Debes ver: {"status":"ok","version":"1.0.0","database":"connected"}

  Ahora intenta hacer login en el Portal Admin de Vercel con:
    admin@aida.com.ve / Admin2024!
  Si funciona, los datos del seed estan en la nube correctamente.

PASO 2.6: Detener el backend local
  Ya puedes detener el backend local (Ctrl+C). No lo necesitas mas.
  Toda la interaccion de aqui en adelante es a traves de los portales
  en Vercel, que hablan con el backend en Railway.

  El seed creo estos datos:
    - 1 Super Admin (admin@aida.com.ve)
    - 2 Clientes de prueba con sus usuarios (4 usuarios en total)
    - Roles, permisos, plantillas, rangos de numeros de control
    - Configuraciones del sistema

6. TROUBLESHOOTING EN PRODUCCION / QA
================================================================================

PROBLEMA: Login dice "Error de conexion" en cualquier portal
  → El portal no puede comunicarse con el backend en Railway
  → Abre DevTools (F12) → Console → busca el error exacto
  → Si dice "CORS policy": La URL del portal no esta en ALLOWED_ORIGINS
    de Railway. Ve a Railway → Variables → agrega la URL del portal
  → Si dice "Network Error": El backend esta caido. Verifica:
    https://TU_URL_BACKEND/health
  → Si dice "404": Falta /api/v1 al final de NEXT_PUBLIC_API_URL en Vercel

PROBLEMA: Login dice "Credenciales invalidas"
  → Verifica que escribiste bien el email y password (ver cheat sheet)
  → Si el seed no ha corrido, no existen los usuarios.
    Vuelve al paso 2 y ejecuta el seed.

PROBLEMA: Login funciona pero despues todo da error "401 Unauthorized"
  → El token de sesion caduco (dura 30 minutos por defecto)
  → Cierra la pestana, abrela de nuevo, y haz login otra vez

PROBLEMA: "403 Forbidden" al intentar acceder a funciones
  → El usuario no tiene el rol correcto
  → Verifica que estas usando las credenciales correctas para ese portal

PROBLEMA: Los portales cargan pero todo esta en blanco
  → La variable NEXT_PUBLIC_API_URL no esta bien en Vercel
  → Ve a Vercel → tu proyecto → Settings → Environment Variables
  → Verifica que NEXT_PUBLIC_API_URL = https://TU_URL_BACKEND/api/v1
  → IMPORTANTE: Si la cambias, debes redesplegar (Deployments → Redeploy)

PROBLEMA: Electro Caribe puede ver datos de Santoni (o viceversa)
  → Esto es un BUG CRITICO de aislamiento multi-tenant
  → Reportar inmediatamente con: que portal, que usuario, que datos se ven

PROBLEMA: El backend en Railway esta caido
  → Ve a https://railway.app/dashboard → tu proyecto → Deployments
  → Verifica que el ultimo deployment esta en "Success" (verde)
  → Si esta en "Failed" (rojo): click en el deployment → View Logs
  → Errores comunes:
    - "Connection refused" a DB: Neon puede estar pausado por inactividad
      Solucion: Ve a Neon → tu proyecto → deberia reactivarse automaticamente
    - "Memory limit exceeded": El plan free de Railway tiene limite
      Solucion: Redespliega o sube de plan

PROBLEMA: Las metricas de uso aparecen en 0
  → Esto es NORMAL si aun no has hecho llamadas a la API
  → Despues de emitir facturas y usar los portales, deben incrementar

PROBLEMA: El Chat IA no responde
  → Verifica que en Railway estan configuradas las variables:
    AI_PROVIDER=groq
    AI_API_KEY=(tu key de Groq)
    AI_MODEL=llama-3.3-70b-versatile
    AI_BASE_URL=https://api.groq.com/openai/v1
  → Si no tienes AI_API_KEY, el chat no funcionara. Obten una en:
    https://console.groq.com/keys (es gratuito)
