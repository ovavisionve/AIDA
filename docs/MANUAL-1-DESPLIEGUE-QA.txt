================================================================================

Asi quedara todo conectado cuando termines:

  VERCEL (6 proyectos separados, uno por portal)
    │
    │  Cada portal hace peticiones HTTPS a:
    │
    ▼
  RAILWAY (1 proyecto, 1 servicio: el backend Python)
    │
    ├──▶ NEON (PostgreSQL 16 — la base de datos)
    │
    └──▶ UPSTASH (Redis 7 — cache y sesiones)

Orden de creacion (IMPORTANTE, seguir este orden):
  1ro: Neon (base de datos) → te dara una URL de conexion
  2do: Upstash (Redis) → te dara otra URL de conexion
  3ro: Railway (backend) → usa las 2 URLs anteriores
  4to: Vercel (portales) → usa la URL que Railway te da

3. PASO A PASO: BASE DE DATOS EN NEON
================================================================================

POR QUE PRIMERO: Railway necesita la URL de la base de datos para arrancar.
Si no la tiene, el backend falla al conectarse.

PASO 3.1: Crear proyecto en Neon
  1. Abre https://console.neon.tech en tu navegador
  2. Si es tu primera vez, te pedira crear cuenta (usa "Sign up with GitHub")
  3. Una vez dentro, veras el dashboard de Neon
  4. Click en el boton verde "Create a project" (esta arriba a la derecha)
  5. Te saldra un formulario:
     - Project name: escribe exactamente → aida-qa
     - Postgres version: selecciona → 16
     - Region: selecciona → US East (Ohio) (o la que te quede mas cerca)
     - Compute size: deja el default (0.25 CU)
  6. Click "Create project"

PASO 3.2: Copiar la URL de conexion
  1. Neon te mostrara una pantalla con "Connection Details"
  2. Veras un recuadro con una URL que empieza con:
     postgresql://neondb_owner:xxxxxxxxxxxx@ep-xxxxx-xxxxx.us-east-2.aws.neon.tech/neondb?sslmode=require
  3. HAZ CLICK en el icono de copiar (cuadradito al lado de la URL)
  4. Pega esa URL en un bloc de notas o donde puedas guardarla
  5. AHORA MODIFICA LA URL: Necesitas cambiar el inicio de la URL.

     Cambiar esto:
       postgresql://neondb_owner:xxxxx@ep-xxxxx...
     Por esto:
       postgresql+asyncpg://neondb_owner:xxxxx@ep-xxxxx...

     Es decir, solo agregas "+asyncpg" despues de "postgresql".

     Tambien cambiar al final:
       ?sslmode=require
     Por:
       ?ssl=require

  6. Ejemplo de como debe quedar tu URL final:
     ANTES:  postgresql://neondb_owner:abc123@ep-cool-rain-456.us-east-2.aws.neon.tech/neondb?sslmode=require
     DESPUES: postgresql+asyncpg://neondb_owner:abc123@ep-cool-rain-456.us-east-2.aws.neon.tech/neondb?ssl=require

  7. Guarda esta URL modificada. La llamaremos TU_DATABASE_URL.
     La necesitaras en el paso 5 (Railway).

PASO 3.3: Crear las extensiones de PostgreSQL
  1. En Neon, en el menu lateral izquierdo, click "SQL Editor"
  2. Veras un editor de texto donde puedes escribir SQL
  3. Escribe exactamente esto (copia y pega):

     CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
     CREATE EXTENSION IF NOT EXISTS "pgcrypto";
     SET timezone = 'America/Caracas';

  4. Click el boton "Run" (triangulo verde, arriba a la derecha del editor)
  5. Debe decir "Query executed successfully" o similar
  6. Si dice error, no te preocupes: probablemente ya existen las extensiones

LISTO. Neon esta configurado. No toques nada mas aqui por ahora.

4. PASO A PASO: REDIS EN UPSTASH
================================================================================

POR QUE SEGUNDO: Railway tambien necesita la URL de Redis.

PASO 4.1: Crear base de datos Redis
  1. Abre https://console.upstash.com en tu navegador
  2. Si es primera vez, crea cuenta (usa "Sign up with GitHub")
  3. En el dashboard, click "Create Database" (boton verde arriba)
  4. Te saldra un formulario:
     - Name: escribe → aida-qa
     - Type: selecciona → Regional (NO Global)
     - Region: selecciona → US-East-1
     - Eviction: deja desactivado
  5. Click "Create"

PASO 4.2: Copiar la URL de conexion
  1. Upstash te llevara al dashboard de tu nueva base de datos
  2. Busca la seccion que dice "REST API" — NO ES ESTA la que necesitas
  3. Busca mas abajo donde dice "Redis Connection"
     o en la parte superior donde hay pestanas: "REST API" | "Redis"
     Click en "Redis"
  4. Veras varias opciones de conexion. Busca la que dice:
     "redis:// ..." o "rediss://..." (con doble S = SSL)
  5. La URL se ve asi:
     rediss://default:AbCdEfGhIjKlMnOpQrSt@us1-shiny-fish-12345.upstash.io:6379
  6. Copia esa URL completa
  7. Guardala. La llamaremos TU_REDIS_URL.

LISTO. Upstash esta configurado.

5. PASO A PASO: BACKEND EN RAILWAY
================================================================================

IMPORTANTE ANTES DE EMPEZAR:
El proyecto AIDA tiene un archivo llamado "Dockerfile" dentro de la carpeta
"backend". Esto significa que Railway va a usar Docker para construir el
backend AUTOMATICAMENTE. Por eso NO veras campos de "Build Command" ni
"Start Command" en la pantalla de Settings. Esto es NORMAL y CORRECTO.
El Dockerfile ya tiene todo lo necesario adentro.

PASO 5.1: Crear proyecto en Railway
  1. Abre https://railway.app/dashboard en tu navegador
  2. Si es primera vez, crea cuenta con GitHub
  3. Click "New Project" (boton morado arriba a la derecha)
  4. Se abre un menu. Selecciona "Deploy from GitHub repo"
  5. Si te pide autorizar GitHub, dale "Authorize Railway"
  6. Veras la lista de tus repositorios. Busca "AIDA" y clickealo
  7. Railway empezara a desplegar. VA A FALLAR — esto es normal porque
     todavia no tiene las variables de entorno. No te preocupes.

PASO 5.2: Configurar el Root Directory
  1. En la pantalla de Railway, veras tu proyecto con un servicio
     (un recuadro/card que dice algo como "AIDA" con un icono)
  2. Haz click en ese servicio (el recuadro)
  3. Arriba veras pestanas: "Deployments" | "Logs" | "Variables" | "Settings" | ...
  4. Click en "Settings"
  5. Busca la seccion "Source" — esta casi al principio
  6. Dentro de Source, busca el campo "Root Directory"
     (dice algo como "The root directory of the project")
  7. Haz click en el campo y escribe exactamente: backend
  8. Presiona Enter o click fuera del campo para guardar

  QUE VERAS DESPUES:
  - Mas abajo, en la seccion "Build", veras que dice "Builder: Dockerfile"
  - Esto es CORRECTO. NO intentes cambiarlo.
  - NO busques campos de "Build Command" ni "Start Command"
  - El Dockerfile que esta en backend/Dockerfile ya tiene los comandos:
      * Instala Python 3.12
      * Ejecuta pip install -r requirements.txt
      * Arranca uvicorn en el puerto que Railway asigna
  - Railway lee ese archivo y hace todo automaticamente

PASO 5.3: Configurar las Variables de Entorno

PASO 5.4: Esperar el despliegue
  1. Despues de agregar las variables, Railway redespleaga automaticamente
  2. Click en la pestana "Deployments" para ver el progreso
  3. Veras un deployment con estado "Building..." (icono naranja girando)
  4. Espera 3-5 minutos. El build hace lo siguiente internamente:
     - Detecta el Dockerfile en /backend
     - Instala Python 3.12
     - Instala las 50+ dependencias de requirements.txt
     - Arranca uvicorn
  5. Cuando termine, el estado cambiara a:
     - "Success" (check verde) = TODO BIEN, sigue al paso 5.5
     - "Failed" (X roja) = HAY ERROR, sigue al paso 5.6

PASO 5.5: Generar URL publica del backend
  1. Click en la pestana "Settings" de tu servicio
  2. Busca la seccion "Networking" (desplazate hacia abajo)
  3. Dentro de Networking, busca "Public Networking"
  4. Veras un boton que dice "Generate Domain"
  5. Click "Generate Domain"
  6. Railway generara una URL como:
     aida-production-xxxx.up.railway.app
     (donde xxxx son caracteres aleatorios)
  7. COPIA ESTA URL COMPLETA y guardala.
     La llamaremos TU_URL_BACKEND.
     Ejemplo: https://aida-production-a1b2.up.railway.app

PASO 5.6: Verificar que el backend esta vivo
  1. Abre una nueva pestana en tu navegador
  2. Escribe en la barra de direcciones:
     https://TU_URL_BACKEND/health
     (reemplaza TU_URL_BACKEND por la URL real del paso 5.5)
     Ejemplo: https://aida-production-a1b2.up.railway.app/health
  3. Debes ver en la pantalla este texto:
     {"status":"ok","version":"0.1.0"}
  4. Si ves eso: EXCELENTE, el backend esta funcionando. Ve al paso 6.
  5. Si NO ves eso, o da error:
     - Vuelve a Railway → click en tu servicio → pestana "Deployments"
     - Click en el deployment mas reciente
     - Click "View Logs" para ver que paso
     - Errores comunes:
       a) "ModuleNotFoundError": Fallo el pip install.
          Solucion: ve a Settings → verifica Root Directory = backend
       b) "Connection refused" a la base de datos:
          Solucion: verifica que DATABASE_URL esta bien copiada
          con postgresql+asyncpg:// al inicio y ?ssl=require al final
       c) "Connection refused" a Redis:
          Solucion: verifica que REDIS_URL esta bien copiada
       d) Si no ves ningun log: el build aun no termino. Espera.

6. PASO A PASO: LOS 6 PORTALES EN VERCEL
================================================================================

COMO FUNCIONA: El repositorio AIDA tiene 6 aplicaciones frontend en
frontend/apps/. Cada una se despliega como un proyecto INDEPENDIENTE
en Vercel. Vas a repetir un proceso similar 6 veces.

IMPORTANTE SOBRE MONOREPOS EN VERCEL:
Vercel es inteligente con monorepos. Cuando le dices que el Root Directory
es "frontend/apps/portal-client", Vercel:
  - Detecta que es parte de un monorepo (por el package.json padre)
  - Automaticamente instala dependencias desde la raiz del monorepo
  - Detecta Next.js y sabe como hacer el build
  - NO necesitas escribir Build Command ni Install Command
  - Si algo falla con dependencias, hay solucion en paso 10

Vas a crear 6 proyectos en Vercel, uno por uno, en este orden:

  # │ Nombre proyecto Vercel │ Root Directory en Vercel              │ Que es
  ──┼────────────────────────┼───────────────────────────────────────┼───────────
  1 │ aida-admin-qa          │ frontend/apps/portal-admin            │ Portal Admin
  2 │ aida-facturador-qa     │ frontend/apps/portal-facturador       │ Facturador
  3 │ aida-cliente-qa        │ frontend/apps/portal-client           │ Cliente
  4 │ aida-validacion-qa     │ frontend/apps/portal-validacion       │ Validacion

  3. Click en la pestana "Console"
  4. Intenta hacer login (email: cualquiera, password: cualquiera)
  5. Si ves un error rojo que dice "CORS" o "blocked by CORS policy":
     → La URL en ALLOWED_ORIGINS no coincide exactamente
     → Revisa que no haya espacios extra, barras finales, o http en vez
       de https
  6. Si ves un error "401 Unauthorized" o "Network Error":
     → CORS esta bien (el error es porque no hay usuario aun)
     → Pasa al paso 8

8. CREAR USUARIO ADMIN Y DATOS INICIALES
================================================================================

NOTA: Para estos pasos necesitas hacer peticiones HTTP al backend.
Puedes usar cualquiera de estas herramientas:
  - El navegador (para peticiones GET)
  - Postman (app gratuita: https://www.postman.com/downloads/)
  - La documentacion interactiva de la API (Swagger)

OPCION MAS FACIL — Usar Swagger (la documentacion interactiva):

PASO 8.1: Abrir la documentacion de la API
  1. En tu navegador, abre:
     https://TU_URL_BACKEND/api/docs
     (ejemplo: https://aida-production-a1b2.up.railway.app/api/docs)
  2. Veras la interfaz de Swagger con todos los endpoints de la API
  3. Si dice "Not Found": la variable DEBUG esta en false.
     Ve a Railway → Variables → cambia DEBUG a true → espera redeploy
     → intenta de nuevo

PASO 8.2: Registrar el primer usuario admin
  1. En Swagger, busca la seccion "Auth"
  2. Busca el endpoint POST /api/v1/auth/register
  3. Click en ese endpoint para expandirlo
  4. Click "Try it out" (boton a la derecha)
  5. En el campo "Request body", borra lo que haya y pega:
     {
       "email": "admin@aida.com.ve",
       "password": "Admin2024!Secure",
       "first_name": "Admin",
       "last_name": "AIDA"
     }
  6. Click "Execute"
  7. Abajo en "Response body" debe aparecer algo como:
     {"id": "...", "email": "admin@aida.com.ve", ...}
  8. Si da error 422: revisa que el JSON este bien formado
  9. Si da error 500: revisa los logs de Railway

PASO 8.3: Hacer login para obtener el token
  1. En Swagger, busca POST /api/v1/auth/login
  2. Click "Try it out"
  3. Pega en el body:
     {
       "email": "admin@aida.com.ve",
       "password": "Admin2024!Secure"
     }
  4. Click "Execute"
  5. En la respuesta veras:
     {"access_token": "eyJhbGc...(token largo)...", "token_type": "bearer"}
  6. COPIA el valor de access_token (todo el texto entre comillas,
     sin incluir las comillas)

PASO 8.4: Autorizar Swagger con el token
  1. En la parte superior de Swagger, busca el boton "Authorize" (candado)
  2. Click en "Authorize"
  3. En el campo "Value", escribe: Bearer (espacio) y pega el token
     Ejemplo: Bearer eyJhbGciOiJIUzI1NiIs...
  4. Click "Authorize" y luego "Close"
  5. Ahora todas las peticiones que hagas desde Swagger llevaran el token

PASO 8.5: Ejecutar el seed (crear roles, permisos y datos iniciales)
  1. Busca la seccion "Admin"
  2. Busca el endpoint POST /api/v1/admin/seed
  3. Click "Try it out" → Click "Execute"
  4. La respuesta debe decir algo como:
     {"message": "Seed completado", ...}
  5. Esto crea:
     - 6 roles predefinidos (super_admin, admin, facturador, etc.)
     - 60+ permisos organizados por modulo
     - Configuraciones del sistema por defecto

10. TROUBLESHOOTING (TODOS LOS ERRORES CONOCIDOS)
================================================================================

─── ERRORES DE RAILWAY ─────────────────────────────────────────────────────────

ERROR: Build falla con "no matching manifest for linux/amd64"
QUE SIGNIFICA: Railway no puede construir la imagen Docker
SOLUCION:
  1. Ve a Settings de tu servicio
  2. Verifica que Root Directory es exactamente: backend
  3. Si sigue fallando, ve a Settings → Build → si ves "Dockerfile"
     como builder, eso esta correcto. NO intentes cambiarlo.
  4. Click "Redeploy" en la pestana Deployments

ERROR: Build exitoso pero la app no arranca (logs dicen "port already in use")
QUE SIGNIFICA: El Dockerfile tenia el puerto hardcoded
SOLUCION: Este error ya fue corregido en el codigo. Si lo ves, haz
  git pull y redespliega.

ERROR: "Connection refused" a la base de datos en los logs
QUE SIGNIFICA: La variable DATABASE_URL esta mal o Neon no es accesible
SOLUCION:
  1. Ve a Variables → click en DATABASE_URL → verifica:
     - Empieza con: postgresql+asyncpg://  (NO postgresql://)
     - Termina con: ?ssl=require  (NO ?sslmode=require)
     - No tiene espacios al inicio ni al final
  2. Ve a Neon → tu proyecto → verifica que esta activo
  3. Redespliega

ERROR: "Connection refused" a Redis en los logs
QUE SIGNIFICA: La variable REDIS_URL esta mal
SOLUCION:
  1. Ve a Variables → click en REDIS_URL → verifica:
     - Empieza con: rediss://  (con doble S) o redis://
     - No tiene espacios
  2. Redespliega

ERROR: Railway dice "Builder: Dockerfile" y no puedo poner Build Command
QUE SIGNIFICA: Railway detecto el Dockerfile y lo usa automaticamente
SOLUCION: Esto es CORRECTO. NO necesitas Build Command ni Start Command.
  El Dockerfile ya contiene todo. Salta ese paso y ve a Variables.

ERROR: No veo la opcion "Generate Domain" en Settings
QUE SIGNIFICA: Estas en la seccion incorrecta
SOLUCION: Dentro de Settings, desplazate hacia abajo hasta encontrar
  "Networking" → dentro de esa seccion esta "Generate Domain"

─── ERRORES DE VERCEL ──────────────────────────────────────────────────────────

ERROR: Build falla con "Cannot find module '@aida/shared'"
QUE SIGNIFICA: Vercel no encuentra el paquete compartido del monorepo
SOLUCION:
  1. Ve a tu proyecto en Vercel → Settings → General
  2. Busca "Root Directory" → verifica que dice:
     frontend/apps/portal-NOMBRE (no frontend/portal-NOMBRE)
  3. Busca "Node.js Version" → cambialo a 18.x si esta en otra version
  4. Click "Redeploy" (ve a Deployments → ... → Redeploy)

ERROR: Build falla con "Type error" o "TypeScript error"
QUE SIGNIFICA: Hay un error de tipos en el codigo
SOLUCION:
  1. Lee el error completo en los logs de build
  2. Reportamelo con el texto exacto del error y lo corrijo

ERROR: Build exitoso pero pagina en blanco
QUE SIGNIFICA: La variable NEXT_PUBLIC_API_URL no esta o esta mal
SOLUCION:
  1. Ve a Settings → Environment Variables
  2. Verifica que existe NEXT_PUBLIC_API_URL
  3. Verifica que el valor es: https://TU_URL_BACKEND/api/v1
     (con /api/v1 al final)
  4. IMPORTANTE: Las variables NEXT_PUBLIC_ se embeben en el build.
     Si la cambias, debes redesplegar:
     Ve a Deployments → click los 3 puntos (...) del ultimo deployment
     → "Redeploy"

ERROR: La pagina carga pero al hacer login dice "Error de conexion"
QUE SIGNIFICA: El frontend no puede contactar al backend
SOLUCION:
  1. Abre DevTools (F12) → Console → busca el error exacto
  2. Si dice "CORS": ve al paso 7 y verifica ALLOWED_ORIGINS
  3. Si dice "Network Error": la URL del backend es incorrecta
     → verifica NEXT_PUBLIC_API_URL en Vercel → redespliega
  4. Si dice "404": falta /api/v1 al final de la URL

ERROR: Login funciona pero despues todo da error "401 Unauthorized"
QUE SIGNIFICA: El token de sesion caduco o no se esta enviando
SOLUCION: Cierra la pestana, abrela de nuevo, y haz login otra vez.
  El token dura 30 minutos por defecto.

ERROR: "403 Forbidden" al intentar acceder a funciones de admin
QUE SIGNIFICA: Tu usuario no tiene el rol de admin asignado
SOLUCION: Ejecuta el seed (paso 8.5) si no lo has hecho.

─── ERRORES DE NEON ────────────────────────────────────────────────────────────

ERROR: "FATAL: role does not exist"
QUE SIGNIFICA: El usuario de la base de datos no existe
SOLUCION: Ve a Neon → Connection Details → verifica el usuario y password
  en tu DATABASE_URL

ERROR: "SSL connection is required"
QUE SIGNIFICA: Falta ?ssl=require al final de DATABASE_URL
SOLUCION: Agrega ?ssl=require al final de la URL en Railway
